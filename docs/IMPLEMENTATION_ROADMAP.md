## Phase 2 — engineering case studies

Phase 1B refines the existing homepage after an independent design review; see `PHASE_1B_DESIGN_REVIEW.md`. The framework, protected headline, project identities and Lab scope remain intact. This refinement does not begin case-study or simulator implementation.

Phase 2A implements AutoMark at `/work/automark/` from the available résumé, original architecture, authentic dashboard and user-confirmed experiences. See `PHASE_2A_REPORT.md` and `AUTOMARK_EVIDENCE.md`. Typed article content and a small architecture Client Component provide an authoring pattern without adding MDX or a diagram framework.

Phase 2A.1 reconciles the supplied authoritative graduate résumé, corrects the queue/AWS-worker architecture, adds reported benchmark observations, updates DAITA/independent work and manages the current public PDF. See `PHASE_2A1_RECONCILIATION.md`. Remaining evidence concerns exact AWS products and handoffs, raw test methodology/logs, endpoint inventory and improved authentic captures. Résumé-supported measurements and responsibilities are retained while these details remain open. EquityGuard and Deloitte were outside Phase 2A scope.

Phase 2B completes EquityGuard at `/work/equityguard/`: independent full-stack narrative, authentic offline React capture, six-tool contract inspector, source-grounded control flow and 9/7/7 test inventory. See `PHASE_2B_REPORT.md` and `EQUITYGUARD_EVIDENCE.md`. Source and suite were reviewed at a pinned revision; 23 tests passed without network access. Retrieval and broader integration coverage remain unresolved in the external project. No Deloitte/secondary case study or Lab simulator was started.

## Phase 3 — Engineering Lab

Build AutoMark's browser-only simulator first: clearly illustrative success, invalid submission and timeout fixtures; never execute arbitrary visitor code. Then agent tool-call inspection (no private reasoning), retrieval exploration and fictional policy demonstrations. Introduce Motion, React Flow or unit-test tooling only when complexity warrants it; lazy-load expensive experiences.

## Phase 4 — personal exploration

Authentic journal entries and personal photography, interactive project/skill mapping, command palette, recruiter overview and a case study about this portfolio. No fabricated activity or arbitrary skill percentages.

## Phase 5 — release preparation

Review real assets and final résumé, test additional browsers/devices, audit WCAG 2.2 AA, repeat production measurements and confirm actual hosting configuration. Target Lighthouse performance ≥90, LCP ≤2.5s, CLS ≤0.1 and field INP ≤200ms. Do not present targets as achieved before measurement. Any publishing requires a separate explicit request.

## Phase 3A — Engineering Lab foundation completed

The landing page and AutoMark Workload Simulator are implemented. Shared foundations cover Lab environment/breadcrumbs/boundaries plus a pure workload engine, derived metrics, browser playback and a dedicated workspace. Three coherent scenarios cover steady work, mixed durations and one timeout. No invalid-submission or worker-unavailability scenario was added because those require additional semantics. See `LAB_SIMULATION.md` and `PHASE_3A_REPORT.md` for state transitions, rendered refinements, verification and limitations.

Future experiments should reuse the environment and accessibility principles while retaining their own composition and state model. Next useful work includes usability testing of the queue/worker relationship, deeper side-by-side run comparison, and permission-cleared technical evidence. No additional Lab experience, recruiter mode, command palette, journal or skill map has begun.

## Phase 3B — five Lab experiences implemented

The Lab now includes Agent Execution Replay, Evidence Journey, Interactive Resolution Workflow and Document Quality & Review alongside AutoMark, which adds completed-run comparison. Each was built, tested and visually refined sequentially. See `PHASE_3B_REPORT.md` and `LAB_COLLECTION_MODELS.md` for exact evidence boundaries, verification and limitations.

Next useful work is physical-device/screen-reader and cross-browser usability testing, richer permission-cleared original evidence, and carefully scoped improvements to mobile context/record focus. No command palette, recruiter mode, journal or skill map has started. Future feature work still requires a new scope; production release/deployment remains separately authorised.
